# /apply — 공고 하나 깊게 보고 자소서 쓰기 (작성 → 검토 → 수정)

작성자가 초안을 쓰고, **맥락을 모르는 별도 검토 에이전트**가 비판한 뒤, 그걸 반영해 고칩니다.
같은 눈으로 쓰고 검토하면 놓치는 걸 잡기 위한 구조입니다.

(흐름은 [ai-job-search](https://github.com/MadsLorentzen/ai-job-search) 의 drafter-reviewer 파이프라인, MIT 를 한국 자소서에 맞게 옮긴 것입니다.)

## 0. 입력 (`$ARGUMENTS`)

- 사람인 공고 주소 → 그 공고
- 숫자 → 보관함의 `id` (`python jobctl.py saved` 로 찾음)
- 긴 텍스트 → 사용자가 붙여넣은 공고 본문
- 문항이 함께 오면 그것을 쓴다 (예: `지원동기 500자, 직무경험 700자`)
- 아무것도 없으면 보관함 목록을 보여주고 고르게 한다

## 1. 재료 모으기

```bash
python jobctl.py profile
python jobctl.py detail <link>
```

- 프로필 `empty` 가 true 면 멈추고 `/profile` 을 먼저 안내한다.
- `IMAGE_ONLY` 면 본문이 이미지다. 추측하지 말고 **본문을 붙여넣어 달라고** 한다.
- `profile` 출력의 `fabrication_rule` 이 이 명령 전체의 최우선 규칙이다.

## 2. 적합도 판단

`.claude/commands/rank.md` 의 **3-1 필수 조건**과 **3-2 점수** 기준을 그대로 쓴다.

- 필수 조건에서 탈락 → 공고 문장을 인용해 알리고 **여기서 멈춘다**. 사용자가 그래도 쓰겠다면 진행.
- 45점 미만 → 이유를 말하고 계속할지 묻는다.
- 통과 → 점수, 맞는 점 3개, 걸리는 점과 **자소서에서 어떻게 다룰지**를 짧게 보여준다.

## 3. 작성자: 초안

먼저 기본 자소서를 읽는다.

```bash
python jobctl.py letters --company 기본
```

**기본 자소서가 있으면 새로 쓰지 말고 그것을 고쳐서 쓴다.** 사용자가 직접 쓴 글이라 문체와 내용을 최대한 살린다.

- `{회사}`, `{분야}`, `{공정}`, `{직무}`, `{교대제}` 를 공고 본문에 맞게 채운다. 공고에 없는 정보면 그 문장을 자연스럽게 고쳐 자리표시를 없앤다.
- 문항이 정해진 공고면 기본 자소서의 문단을 문항에 맞게 재배치하고 글자수에 맞춰 줄이거나 늘린다. 늘릴 때 재료는 프로필에서만 가져온다.
- 공고가 강조하는 업무(예: 믹싱, 증류, 설비 보전)와 가장 가까운 경험을 앞으로 올린다.
- 근무지가 구미 인근이면 "인근 거주" 를 넣고, 멀면 기숙사·이주 가능 여부는 사용자에게 묻는다 (지어내지 않는다).

기본 자소서가 없거나 사용자가 "새로 써줘" 라고 하면 아래 기준으로 처음부터 쓴다.
문항이 없으면 `profile` 의 `default_questions` 를 쓰고, 글자수가 없으면 문항당 500자 안팎.

- 각 답변의 근거는 프로필의 `episodes`, `career`, `skills`, `certificates` 에서만 가져온다.
- 공고 본문에서 이 회사가 실제로 원하는 것(교대·설비·품질·안전 등)과 내 경험을 **연결**한다.
- 재료가 모자라면 지어내지 말고 그 자리에 `[보충 필요: 무엇]` 을 남긴다.
- 첫 문장은 결론부터. "저는 ~에서 태어나", "귀사의 무궁한 발전" 같은 서두 금지.

## 4. 검토자: 비판

Agent 도구로 `general-purpose` 에이전트를 하나 띄운다. 검토자는 새 맥락이므로 아래를 **프롬프트에 직접** 넣는다
(파일을 다시 읽게 하지 말 것): 프로필 JSON 전체, 공고 본문, 문항과 글자수, 초안 전체.

검토자에게 시킬 일:

1. **사실 검증** — 초안의 모든 경력·숫자·자격증·성과가 프로필에 있는가. 없는 것은 문장을 인용해 전부 나열.
2. **문항 적합성** — 묻는 것에 답했는가 (지원동기에 성장과정을 쓰는 식의 어긋남).
3. **상투 표현** — "성실함", "열정", "최선을 다하겠습니다" 처럼 누구나 쓸 수 있는 문장. 구체적 대안 방향 제시.
4. **공고 연결** — 공고가 강조한 조건 중 프로필로 답할 수 있는데 빠진 것. 단, 키워드를 억지로 끼워 넣으라고 하지 말 것.
5. **분량** — 문항별 글자수(공백 포함)와 제한 대비 과부족.

반환 형식: 문항별로 `고칠 문장 → 바꿀 방향 → 이유`, 그리고 사실 검증 실패 목록.

## 5. 작성자: 수정

검토를 반영해 고친다. 단,

- 검토자가 제안했더라도 **프로필에 근거가 없는 내용은 넣지 않는다.** 대신 `[보충 필요]` 로 남긴다.
- 사실 검증 실패 항목은 전부 삭제하거나 프로필 근거로 바꾼다.
- 검토 의견 중 받아들이지 않은 것은 이유를 한 줄로 적는다.

## 6. 결과

문항별 최종본과 글자수를 보여주고, 아래를 덧붙인다:

- `[보충 필요]` 목록 — 사용자가 채워줄 경험. 받으면 `/profile` 로 프로필에도 넣자고 제안
- 검토에서 가장 크게 바뀐 점 1~2개

**"앱에 저장할까요?"** 라고 묻고, 동의하면:

1. 공고가 보관함에 없으면 먼저 넣는다 — 앱은 보관함 공고 아래에만 자소서를 보여준다.
   ```bash
   python jobctl.py save --file <임시파일>.json
   ```
2. 문항마다 저장한다. `--company` 는 `saved`/`search` 출력의 `company` 를 **글자 그대로** 쓴다
   (`(주)포스코` 와 `포스코` 는 앱에서 다른 회사다).
   ```bash
   python jobctl.py save-letter --company "<company 그대로>" --question "<문항>" --file <임시파일>.txt --job-id <보관함 id>
   ```

같은 회사·문항이면 덮어쓴다. 저장하면 앱 보관함의 해당 공고 아래 **자소서**에 바로 보인다.
