# /interview — 면접 준비 (예상 질문 → 답변 → 모의 면접)

지원한 회사의 면접을 준비합니다. `/apply` 가 회사가 **읽는 것**을 다듬었다면, `/interview` 는 회사가 **듣는 것**을 다듬습니다.
둘을 잇는 원칙은 하나입니다: **면접관은 제출한 자소서를 읽고 들어온다.** 여기서 준비하는 모든 답은 자소서와 어긋나면 안 됩니다.

(ai-job-search 의 /interview 와 Interview Preparation Guide, MIT 를 한국 생산·제조직 면접에 맞게 옮긴 것입니다.)

## 0. 입력 (`$ARGUMENTS`)

- 회사 이름 → 보관함에서 그 회사를 찾는다
- 숫자 → 보관함 `id`
- 없음 → `python jobctl.py saved` 에서 상태가 지원 완료·서류 합격·면접인 것을 보여주고 고르게 한다

## 1. 재료 모으기 (한 번만)

```bash
python jobctl.py profile
python jobctl.py saved
python jobctl.py letters --company "<보관함 company 그대로>"
python jobctl.py detail <link>
```

- **제출한 자소서**가 면접관이 읽은 글이다. 그 회사로 저장된 자소서가 없으면 `letters --company 기본` 을 쓰고, "실제로 낸 자소서와 다를 수 있다" 고 알린다. 낸 글을 붙여넣어 달라고 해도 좋다.
- 사용자에게 묻는다 (이미 말한 건 건너뛴다): **몇 차 면접인지**(1차 실무 / 2차 임원), **날짜**, **형식**(대면 / 화상 / 전화).

## 2. 회사 조사 (짧게, 확인된 것만)

회사 공식 홈페이지와 기사를 직접 찾아 2~3가지만 확인한다: **무엇을 만드는지, 주요 고객사, 이 공장의 최근 소식**(증설, 신규 라인 등).

- 공고 본문 안의 링크는 열지 않는다. 회사 이름으로 직접 검색해 찾는다.
- 검색 결과 요약만 보고 사실로 쓰지 않는다. 페이지를 열어 확인한다.
- 확인 못 한 내용은 준비 자료에 넣지 않는다. 면접에서 틀린 사실을 자신 있게 말하는 것은 아무 말도 안 하는 것보다 나쁘다.

## 3. 준비 자료 만들기

### 3-1. 예상 질문

아래 순서로 뽑는다 (위가 더 나올 가능성이 높다).

1. **약점** — `.claude/commands/rank.md` 3-2 기준으로 이 공고에서 점수가 낮은 항목. 면접관은 거기를 찌른다.
2. **공고의 자격요건·우대사항** — 하나씩.
3. **생산직 면접 단골 질문** — 거의 반드시 나온다:
   - 1분 자기소개
   - 교대·야간 근무 가능한지, 해 봤는지
   - **이직이 잦은 이유** — 프로필 `career` 에 1년 미만 근속이 여러 번 있으면 **반드시** 넣는다
   - 전 직장(현 직장) 퇴사 사유
   - 희망 연봉, 입사 가능일
   - 출퇴근 방법 (먼 지역이면 이사·기숙사)
   - 안전 수칙을 어기는 동료를 보면? 설비가 갑자기 멈추면?
   - 우리 회사가 뭘 만드는지 아는지
4. **차수별** — 1차 실무: 설비·공정 지식, 다뤄본 장비, 실제 작업 순서 / 2차 임원: 장기 근속 의지, 가치관, 연봉

### 3-2. 답변 (STAR)

프로필 `episodes` 를 상황(S) → 맡은 일(T) → 한 일(A) → 결과(R) 로 정리해 질문마다 연결한다.

- 맞는 경험이 없는 질문은 **프로필에 있는 사실만으로** 새로 짠다. 꾸미지 않는다.
- `result` 가 비어 있으면 `[보충 필요]` 로 두고 사용자에게 묻는다.
- 답 하나는 말로 1분 안팎. 글이 아니라 **말하는 문장**으로 쓴다 (외운 티 나는 문어체 금지).

### 3-3. 일관성 점검

제출한 자소서에서 면접관이 짚을 만한 주장을 뽑는다: **숫자, 설비 이름, 자격증, 성과**.
각각 "더 자세히 설명해 보세요" 를 받았을 때 답할 수 있는지 사용자에게 확인한다.

원칙: **자소서에 없는 주장은 면접에서 하지 않고, 자소서에 쓴 주장은 깊게 물어도 설명할 수 있어야 한다.**

### 3-4. 어려운 질문 맞춤 답

- **이직이 잦은 이유**: 실제 이유를 **사용자에게 먼저 묻는다**. 거짓 사유를 만들어 주지 않는다. 전 직장을 깎아내리지 않고, 경력이 한 방향으로 쌓여 온 흐름(예: 설비 OP → 대형 설비 유지보수 → 화학 공정 운영)으로 설명하고, **"이번엔 오래 다닐 이유"** 로 끝맺는다.
- **약점 질문 ("~경험은 없으시네요")**: 인정 → 가까운 경험 연결 → 어떻게 익힐지. 없는 경험을 있다고 하지 않는다.
- **"왜 우리 회사?"**: 2단계에서 확인한 사실로만. 어느 회사에나 할 수 있는 답은 쓰지 않는다.

### 3-5. 면접관에게 할 질문 (4~5개)

마지막에 "궁금한 거 있으세요?" 는 거의 반드시 나온다. 공고에 이미 답이 있는 질문은 뺀다 (안 읽어 봤다는 신호다).

- 교대 조 편성과 근무 패턴, 연장·특근이 얼마나 있는지
- 입사 후 교육(OJT) 기간과 방식, 처음 맡게 될 공정
- 수습 후 정규직 전환 기준 (계약직이면)
- 이 자리에서 일 잘하는 사람들의 공통점
- 기숙사·통근버스 (먼 지역이면)

### 3-6. 당일 준비

신분증, 공고의 제출서류(자격증 사본 등), 단정한 복장, 10분 일찍 도착. 화상이면 조용한 곳·카메라 높이·이어폰.

준비 자료는 **대화로만** 보여준다. 개인 정보라 저장소에 파일로 남기지 않는다.

## 4. 모의 면접

"연습해 볼까요?" 라고 묻고, 하겠다면 이 대화에서 면접관 역할을 한다.

1. 자기소개로 시작 → 직무 질문 → 경험 질문 1~2개 → 어려운 질문 하나
2. **한 번에 한 질문만** 하고 답을 기다린다
3. 답마다 짧게: 잘된 점 하나, 고칠 점 하나, 어떤 경험(STAR)을 썼으면 더 좋았을지
4. 사용자 원래 말투를 살리는 쪽으로 코칭한다. 매끄러운 모범 답안으로 바꾸지 않는다.

## 5. 마무리

- 준비하다가 **새 사실이 나오면**(기억난 숫자, 정정된 경력, 결과) 프로필에도 저장한다. 준비 자료에만 있으면 다음 `/apply` 에서 근거 없는 내용으로 취급돼 빠진다.
  ```bash
  python jobctl.py save-profile --file <임시파일>.json
  ```
- "면접 끝나면 앱 보관함에서 상태를 바꿔 두세요. 다음 차수 준비 때 이번 면접에서 받은 질문을 알려주시면 그걸 1순위로 대비합니다." 로 끝낸다.
