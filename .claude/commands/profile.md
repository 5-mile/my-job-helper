# /profile — 내 프로필 채우기 (경험 캐내기 인터뷰)

`/rank` 와 `/apply` 는 프로필을 근거로 채점하고 자소서를 씁니다. **자소서가 부실한 건 대개 문장력이 아니라
재료 탓**이라, 여기서 경험을 깊게 캐냅니다. 앱의 **내 프로필** 탭과 같은 데이터입니다.

(인터뷰 규칙은 [cover-letter-team](https://github.com/djfksjd/cover-letter-team) 의 Interviewer,
경험 6단계와 숫자 대체 기준은 [jobstack](https://github.com/thesun4sky/jobstack) 의 experience-methods 를
옮긴 것입니다. 둘 다 MIT.)

## 1. 현재 상태 확인

```bash
python jobctl.py profile
```

`empty` 가 true 면 처음부터, 아니면 **비었거나 얕은 곳만** 묻는다. 이미 답한 건 다시 묻지 않는다.
특히 `[확인 필요]` 가 붙은 항목은 사용자에게 직접 확인받기 전까지 사실로 쓰지 않는다.

## 2. 시작하며 알릴 것

- 어떤 질문이든 **"모름", "건너뛰기"** 로 답해도 된다
- 회사 내부 수치나 공개하기 싫은 건 말하지 않아도 된다

## 3. 기본 항목

이력서·자소서 파일이나 텍스트가 있으면 거기서 먼저 뽑고, 없는 것만 묻는다.

| 항목 (키) | 물어볼 것 |
| --- | --- |
| `career` | 다닌 회사·기간·맡은 일 (생산직이면 라인/설비/교대 여부까지) |
| `education` | 최종 학력·전공 |
| `certificates` | 자격증·면허 |
| `skills` | 다룰 수 있는 설비·도구·프로그램 |
| `desired_role` | 원하는 직무·지역 범위·제외할 직무·교대 가능 여부·기숙사 |
| `strengths` | 강점 — 반드시 그걸 보여주는 실제 장면과 함께 |

## 4. 경험 캐내기 (가장 중요)

`episodes` 가 자소서의 재료다. 경험 하나를 아래 6단계로 쪼개 묻는다.
**하나라도 비면 아직 소재가 아니다** — 빈 단계만 골라 묻는다.

| 단계 | 질문 |
| --- | --- |
| 1. 이름 | 이 일을 한 줄로 부르면? |
| 2. 문제 | 무엇이 문제였나? 누가·언제·얼마나 |
| 3. 내 몫 | 그중 내가 맡은 건 정확히 어디까지였나? |
| 4. 다르게 한 행동 | 내가 무엇을 어떻게 했나? 왜 그렇게 했나? |
| 5. 확인되는 변화 | 무엇이 달라졌고, 그걸 어떻게 알았나? |
| 6. 직무 연결 | 지원할 일의 어떤 부분과 닿아 있나? (이건 Claude가 판단해도 된다) |

### 묻는 법

- **한 번에 1~2개만** 묻는다. 답이 짧거나 뭉뚱그려지면 그 자리에서 꼬리질문으로 파고든다.
- **유도 질문 금지.** 답을 먼저 내밀고 확인만 받지 않는다.
  - ❌ "대략 20% 정도였나요?", "고장 대응 시간이 줄었겠죠?"
  - ⭕ "수치로 기억나는 게 있나요? 없으면 넘어가도 됩니다.", "그 뒤로 뭐가 달라졌나요?"
- 숫자를 기억 못 하면 지어내지 않는다. 아래 중 하나라도 나오면 충분하다 (위에서부터):
  1. 전후 변화 — "이전엔 A였는데 이후 B" (정성이어도 됨)
  2. 내 몫의 범위 — "설비 10대 중 3대 담당"
  3. 남의 반응 — 사수·반장이 한 말, 내가 만든 양식이 계속 쓰임
  4. 작은 숫자 — "한 달에 두세 번", "3개월간"
  5. **1분간 설명 못 하는 숫자는 쓰지 않는다**

### 검증 질문 (경험마다, 기존 답에서 빠진 것만)

- 내가 직접 한 일인가, 팀이 한 일인가? → 팀 결과와 내 행동을 나눠 적는다
- 결정했나, 제안했나, 실행만 했나? → 실행만 한 일을 결정한 것처럼 쓰지 않는다
- 그 숫자는 잰 값인가, 기억으로 짐작한 값인가?
- 당시에 그렇게 판단했나, 지금 돌아보며 든 생각인가?

### 생산직이라면 이런 경험이 재료가 된다

설비가 멈췄을 때 한 일 · 불량을 먼저 발견한 일 · 작업 순서나 점검표를 고친 일 ·
신입에게 가르친 일 · 교대 인수인계에서 사고를 막은 일 · 안전 수칙 때문에 작업을 멈춘 일 ·
다른 조나 부서와 맞춰서 해결한 일

## 5. 저장

받은 항목만 JSON으로 저장한다. 보낸 항목만 덮어쓰고 나머지는 그대로 둔다.

- `episodes` 의 `result` 에는 확인 방법을 괄호로 붙인다: `(측정)`, `(기억 추정)`, `(정성)`
- 사용자에게 확인받지 못한 내용은 앞에 `[확인 필요]` 를 붙인다. `/apply` 는 이걸 쓰지 않는다
- 사용자가 "모름"이라고 한 칸은 비워 둔다

```bash
python jobctl.py save-profile --file <임시파일>.json
```

저장 후 `python jobctl.py profile` 로 다시 읽어 확인하고, 경험마다 6단계 중 아직 빈 단계를 한 줄로 알려준다.
